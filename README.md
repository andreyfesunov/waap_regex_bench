# waap_regex_bench

- [dataset/](dataset/) - папка с исходниками, в том числе [dataset/legitimate/](dataset/legitimate/) - целевой датасет, [dataset/malicious/](dataset/malicious/) - вредоносный, [dataset/nmap-service-probes](dataset/nmap-service-probes) - список regex по nmap

## Решения

### По работе с регулярками

#### Наивный проход по регулякам

Проход по 1e6 записей с проверкой каждого из 12000 регулярных выражений. 

С одной стороны быстро и просто в реализации, с другой стороны 12 миллиардов (1e6 записей * 12000 regex) вызовов regex с отсутствием возможности заранее оптимизировать выражения.

Можно использовать в качестве baseline для оценки эффективности последующих методов.

#### Наивный параллельный проход

Можно распределить запросы между N потоками, каждый из которых по-прежнему будет проверять все regex сигнатуры.

Из преимуществ - относительно простое увеличение производительности.

Из минусов - то же число regex, масштабирование ограничится мощностью машины.

#### Предобработка регулярных выражений

Предварительно можно скомпилировать совместимые регулярки в единую базу и проверять одну запись обращением к regex-движку.

Из преимуществ - оптимизация сигнатур, снижение накладных расходов на проверки.

Из недостатков - неполная совместимость с PCRE (Perl Compatible Regular Expressions), стоимость компиляции + потребление памяти скомпилированный базы.

Выбрано в качестве основного кандидата для реализации, так как заранее известен список регулярных выражений, с которыми предстоит работать, потоу их можно предварительно обработать.

Будет использоваться библиотека [Hyperscan](https://github.com/intel/hyperscan).
